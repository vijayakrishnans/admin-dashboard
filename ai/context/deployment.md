## Database

| environment | /api/health reports |
|---|---|
| stage | database reachable, schema migrated |
| prod | database reachable, schema migrated |

Each environment is its own Supabase project (`admin-dashboard-stage`,
`admin-dashboard-prod`), reached only through the Worker's Hyperdrive binding. The
schema is db-migrate's (`packages/db/src/migrations`): the products
table, the template's ten products, and the key Auth.js signs sessions with,
generated once per database into `app_private.secrets`. Every table in
`public` has row-level security and no policy, and `app_private` is not a
schema the Data API exposes, so Supabase's Data API serves none of it.

| secret | where | what it is |
|---|---|---|
| `CLOUDFLARE_API_TOKEN` | the workspace | BROKERED from its Cloudflare connection (`workers-deploy`): deploys the app's Worker |

| `AUTH_GITHUB_ID`, `AUTH_GITHUB_SECRET` | `admin-dashboard` on stage and on prod, once the owner sets them | the GitHub OAuth App's client id and secret, read by the Worker's build — optional: without them the dashboard has no sign-in |

Brokered secrets are minted per run, so no long-lived value is at rest. The
session key is generated inside each environment's database by the
migrations and never leaves it except to the Worker, which reads it through
its Hyperdrive binding. What the workspace holds right now (every secret by
name, and its integrations and their health) is on the console's Secrets and
Integrations pages for `org_96200307fa70439aa826358c096a470d`.
